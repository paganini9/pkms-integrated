# 1단계 킥오프 — "저작 루프 라이브화" (T-92 · T-94 · T-93)

> 근거: `포스트g3-문제정의-개선로드맵.md` 1단계(핵심). 목표: **"엔지니어가 저작한 새 지식이 satisfy에 실제로 반영된다"를 최소 실증.** ③이 드러낸 핵심 결함(저작 루프 미배선) 복원.
> **상시 하드 게이트**: satisfy **시드 회귀 전건 그린**(sat-good/bad/scope-A/B/pending) — 새 배선이 시드 판정을 바꾸면 안 됨(리팩터-그린). + **라이브 증명**: K2 저작 후 satisfy 판정이 실제로 바뀐다.
> 순서: T-92(선결 버그) → T-94(타입 판정) → T-93(영속·라이브). 93·94는 결합(저장하려면 타입 판정 선결).

---

## T-92 (P0) — 라벨→IRI 새니타이징 (선결 버그)
- **현재**: 공백 라벨("오존 노출")로 IRI 생성 시 500 크래시(`oxigraph.py:172`). violations 0 초안도 저장이 죽음.
- **개선**: IRI local part를 **슬러그화(공백·특수문자 안전) 또는 결정론 해시**로 생성, 표면형은 `rdfs:label`로 보존, **멱등**(같은 라벨→같은 IRI), 기존 시드 IRI 불변.
- **DoD**: "오존 노출"·특수문자 라벨 저장 201, 라벨 보존, 시드 회귀 불변.

## T-94 (P2) — 온톨로지 canonical 타입으로 판정 (LLM 타입 불신)
- **현재**: `WiperBlade ⊑ PartType`인데 provider가 Component로 붙이면 그대로 검증 → "고무 블레이드" 저장 불가.
- **개선**: 추출 개념 **라벨→IRI 해석**(어휘층/label index, T-73 재사용) 후 **온톨로지 canonical type**을 판정에 사용(LLM type은 힌트만). 알려진 개념=온톨로지 타입, 미지=OOV 경로.
- **DoD**: LLM이 Component로 줘도 "고무 블레이드"→WiperBlade(PartType)로 해석·저장.

## T-93 (P1 + Causation 배선) — 저작→파생→영속→satisfy 소비 (핵심)
- **현재**: 저장은 트리플만. 규칙은 `rules.ttl` 정적 시드에서만 컴파일, 저장 응답 `derived`는 일회용(영속 안 됨). Causation 저장 그래프에 0행.
- **개선**:
  1. 도메인 지식 문장 저장 시 → 추출에서 **구조화 규칙**(조건·기전·증상·극성·카테고리) 파생 + **Causation reify**(T-91) + SHACL 컴파일.
  2. 파생 **구조화 규칙을 저작 오버레이로 영속**(단일 진실원; **T-85 오버레이 패턴 재사용**). Causation 노드를 **저장 그래프에 실제 기록**(0행 아님).
  3. 컴파일러(`gen_shacl`)와 satisfy가 **시드 `rules.ttl` + 저작 오버레이를 함께** 소비하도록 배선. **카테고리 스코프(CD-4) 유지.**
- **라이브 증명(플래그십)**: K2(오존→균열)를 완전 접지·저장한 뒤, 해당 설계에 대한 satisfy 판정이 **시드만일 때와 달라진다**(새 지식이 검증에 반영).
- **하드 게이트**: 저작 오버레이가 비었을 때 satisfy **시드 회귀 전건 불변·그린**.

## 종합 DoD (1단계 완료 조건)
- 공백/특수 라벨 저장 201 (T-92).
- "고무 블레이드"→WiperBlade 온톨로지 타입 판정·저장 (T-94).
- **K2 저작 → satisfy 판정 변화** (T-93 라이브 증명).
- **satisfy 시드 회귀 전건 그린** (상시 하드 게이트).
- Causation 저장 그래프에 기록(0행 아님).
- 전체 pytest·vitest·계약 그린. 각 단계 한글 커밋+push.
