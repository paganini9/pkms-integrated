# PKMS 통합 — 수용 기준 & 테스트 시나리오

> 작성일 2026-07-09 · 상태 draft-v0.1 · SRS/기술설계와 짝. 도메인 수치는 와이퍼 6문장.

## 1. 시나리오별 수용 기준 (Given-When-Then)

**AC-1 (SC-1 지식 입력·검증·저장, FR-01~03)**
- Given "겨울철 저온에서 고무 블레이드는 소음이 발생한다" 입력
- When 추출 실행
- Then 개념(겨울철·고무·소음)·관계(고무 causes 소음)가 스트리밍되고, `경도 causes 겨울철` 같은 range 위반은 amber 경고로 표시된다. 승인 시 KnowledgeSentence·mentions·derivesRule이 저장되고 지식맵에 나타난다.
- And 저장 시 규칙·SHACL이 문장에서 파생되고, 엔지니어에겐 **문장 + 파생 요약**이 보인다(규칙 직접편집 없음; 편집=문장→재파생).

**AC-1P (SC-1P 프로젝트 요구사항, FR-3b)**
- Given 프로젝트 생성, 적용 지식=소음+떨림, 자연어 "겨울철에도 소음이 없고 중형 SUV에서 떨림이 없어야 한다"
- When 저장
- Then RB_Winter(forbids Noise)·RB_NoChatter(forbids TipChatter)로 파싱·저장. 미지 증상 참조 시 "지식 추가" 유도.

**AC-scope (프로젝트 지식 범위, FR-3c)**
- Given 동일 설계 A(고무·600·8N·simple·SUV)
- When 프로젝트 A(소음+떨림) vs 프로젝트 B(떨림만)에서 satisfy
- Then A = 4위반(S1·S3/S5·S4·S6), B = 3위반(S3/S5·S4·S6, **소음 미적용**).

**AC-2 (SC-2 satisfy, FR-04·05)** ★
- Given 설계 A = 고무·600mm·8N·simple·중형SUV, 요구거동 = 겨울저소음 ∧ 떨림없음
- When satisfy 실행
- Then 판정 = ⛔ 불만족, 위반 근거 = S1(소음)·S3·S4·S6(떨림), 허용 대안 = 실리콘/≤599mm/≥10N/complex.
- And 설계 B = 실리콘·550mm·12N·complex·세단 → ✅ 만족(근거 S2·S5).

**AC-3 (SC-3 환각비교 Q&A, FR-06~09)**
- Given "중형 SUV에 고무 600mm 써도 될까?"
- When 비교 모드
- Then LLM 단독="가능"(원답변)과 온톨로지="S3·S1 위반, 대안 실리콘/≤599mm"가 나란히 표시되고 불일치 하이라이트 + 위반율/일치율. 자유질의는 RAG 검색 문장이 규칙으로 검증된 뒤 출처와 함께 답한다.

**AC-4 (SC-4 지식맵, FR-10)**
- Given 지식맵, 증상 필터=TipChatter
- When 문장 S3 클릭
- Then S3·S4·S5·S6·ChatterRule·관련 개념이 하이라이트되고, 원문·출처·mentions가 표시되며, 이행 관계는 점선으로 나타난다.

**AC-6 (SC-6 상위 온톨로지, FR-12)**
- Given 관리자, DesignedBehavior에 satisfy 관계 편집
- When 일관성 검사
- Then OK/모순 결과 + M1 subClassOf 영향분석. disjoint 위반 도입 시 차단·설명. 비관리자는 403.

**AC-7 (SC-7 규칙·SHACL, FR-13)**
- Given SUV 안전길이 599→595 변경
- When dry-run
- Then 임시 M2로 새 위반 미리보기. 저장 시 영향받는 M2 인스턴스 목록 표시.

**AC-8 (SC-8 거버넌스, FR-14)**
- Given custom 클래스 "Material2" 생성 후 builtin "Material" 삭제 시도
- Then custom은 생성/삭제 정상, builtin 삭제는 400(BUILTIN_LOCKED), 비관리자 편집 403.

## 2. 평가 루브릭 (LLM-as-Judge)

| 기준 | 정의 | 통과선 |
|------|------|--------|
| 정확성 | satisfy·검증 결과가 6문장 규칙과 일치 | 결정론 100% 일치 |
| 근거성 | 답변이 문장·규칙 IRI를 인용 | P0 답변 전건 출처 |
| 안전성 | 환각 답변을 검증답변과 구분·차단 | 위반 시 저장/채택 차단 |
| RAG 충분성 | 검색 문장이 규칙 검증을 통과한 것만 사용 | 미검증 근거 0 |

## 4. 실패 케이스 목록

| 케이스 | 기대 동작 |
|--------|-----------|
| LLM 오류/타임아웃 | Circuit Breaker → Mock 폴백 or 재시도, 사용자엔 "다시 시도" 안내 |
| 추출 range 위반 | 저장 차단 + 수정 유도(HITL) |
| satisfy 수치 누락 | SHACL 필수속성 경고, 판정 보류 |
| 도메인 밖 질의 | "명세 근거 없음" 명시(억지 답 금지) |
| reasoner 지연 | 시그니처 캐시 히트, 미스 시 진행 표시 |
| 트리플/벡터 불일치 | /save 트랜잭션 실패 시 롤백(양쪽 원자성) |
