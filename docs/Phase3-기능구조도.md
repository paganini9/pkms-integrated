# PKMS × Ontology 통합 재기획 — Phase 3 : 기능구조도 (FSD)

> 작성일 2026-07-09 · 상태 **draft-v0.1 (검토용)**
> 조직 축: **역할 중심(엔지니어 워크스페이스 / 관리자 콘솔) + 작업흐름 + 공통 플랫폼(횡단)**
> 태그: `[계승]` dev-system 유지 · `[이식]` pkms-web에서 · `[강화]` 통합하며 개선 · `[신규]` 새로 도입

---

## 1. 최상위 구조

```
PKMS 통합 시스템
├── A. 엔지니어 워크스페이스 (P1)   — 입력 → 검증 → 탐색 → 질의
├── B. 관리자 콘솔 (P2)            — 상위 온톨로지 · 규칙 · 거버넌스
└── C. 공통 플랫폼 (횡단)          — 추론엔진 · AI · 저장 · API/보안
```

두 워크스페이스는 **공통 플랫폼(C)** 의 추론엔진·AI·저장·API를 공유한다. 환각비교·명세검증은 A와 B 양쪽에서 호출되는 C의 능력이다.

## 2. A. 엔지니어 워크스페이스 (P1)

**A1. 지식 입력·구조화** *(SC-1)*
- A1.1 SmartInput 자연어 입력(SSE 스트리밍) `[계승]`
- A1.2 개념·관계 추출(AI Gateway) `[계승]`
- A1.3 명세검증: 추출결과 → OWL/SHACL 검증(위반=환각후보) `[계승·강화]`
- A1.4 지식 저장 + 문장·규칙·증상 자동 연결 `[강화]`

**A2. 설계 검증 (satisfy)** *(SC-2)* ★ 온톨로지 핵심
- A2.1 설계 인스턴스 입력(재질·길이·스프링·형상·차종) `[신규]`
- A2.2 요구거동(RequiredBehavior) 선택/정의 `[신규]`
- A2.3 satisfy 판정(DB ⊑ RB) + justification `[신규]`
- A2.4 위반 근거 지목 + 허용 대안 추천(실리콘/≤599mm/≥10N/complex) `[신규]`

**A3. 지식맵·탐색** *(SC-4, SC-5)*
- A3.1 다층 지식맵 뷰(M0/M1/M2, SPARQL→Cytoscape) `[계승·강화]`
- A3.2 필터(층/증상/문장)·검색 `[강화]`
- A3.3 개념·문장 상세 + 출처 추적 `[계승]`
- A3.4 설계안 비교(VisualDiff) `[계승]` *(P1)*

**A4. 질의·환각비교** *(SC-3)* ★ 시연 1급
- A4.1 Q&A Layer A(규칙질문)/B(설계검증질문) `[이식]`
- A4.2 환각비교 모드(LLM 단독 ‖ 온톨로지 검증, 3-토글) `[이식·강화]`
- A4.3 신뢰지표(LLM→위반율·일치율·위반심각도) `[이식]`

## 6. 통합 요약 — 무엇이 새로 생기나

- **[신규] 핵심**: satisfy 엔진(C1.3) + 설계검증 워크스페이스(A2) + /satisfy API — 온톨로지의 실무 가치를 정면화.
- **[이식] 핵심**: 환각비교 모드(A4.2)·SHACL explain(C1.4)·Q&A 2레이어(A4.1)·M0/M1/M2 대시보드(C3.4)·SHACL 빌더(B2.2) — pkms-web의 온톨로지 네이티브 강점.
- **[계승] 대부분**: SmartInput·상위 온톨로지 편집기·AI Gateway·reasoner — dev-system의 프론트·기능 셸. **데이터층은 RDF/SHACL(pkms-web rdflib/pySHACL 계승)** 로 단일화.
- **[보류]**(비목표): 규정 PDF 추출·FMEA·파인튜닝(KG-FIT/OntoTune/K-ON).

**다음(Phase 4)**: 이 기능구조를 화면군(IA·내비게이션)으로 옮기고 화면별 요구사항·와이어프레임을 작성한다.
