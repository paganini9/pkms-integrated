> 작성일 2026-07-09 · 상태 draft-v0.1 · SRS와 짝. 아키텍처는 Node BFF + Python 지식·추론 서비스 하이브리드.

## 1. 시스템 아키텍처

```
React 프론트 (dev-system UX, Vite+TS+Tailwind+Cytoscape)
   │ REST / SSE
Node/Express BFF (API Gateway)
   ├─ 인증·세션·권한 게이트 (Mock-Role → 배포 JWT)
   ├─ AI Gateway (Claude/Gemini/Mock) — LLM 생성(추출·Q&A 초안)
   ├─ SSE 스트리밍
   └─ 지식 서비스 호출 (HTTP, REASONER/KNOWLEDGE_URL)
        │
Python 지식·추론 서비스 (FastAPI)   ← 지식 단일 진실원
   ├─ 트리플스토어  Oxigraph (임베디드 영속, SPARQL 1.1)  ┐
   ├─ reasoner      owlready2+HermiT (OWL EL 분류·일관성) │ IRI로 상호 연결
   ├─ SHACL         pySHACL (CWA 게이트)                  │
   ├─ 규칙 컴파일러  문장→구조화 규칙→SHACL·인과엣지 (카테고리 필터) │
   ├─ satisfy 엔진  subsumption + SHACL/구간비교기 + 무증상 │
   └─ 벡터 인덱스   Chroma (임베디드) + 임베딩(다국어 ST/MOCK) ┘
```

**데이터 흐름(핵심 루프)**: 자연어 → BFF(AI Gateway 추출) → 지식서비스(/validate: OWL/SHACL) → 위반 표시·승인 → /save(트리플스토어 + 벡터 upsert) → 지식맵. 설계검증: 설계 인스턴스 → /satisfy(3단계) → 판정·근거·대안.

## 3. 파이프라인 (Agentic Workflow 대체 — 이 시스템은 파이프라인)

LangGraph식 멀티에이전트는 불필요(단일 책임 파이프라인으로 충분). 3개 파이프라인:

- **추출 생성기–검증기**: `/extraction/full`(LLM 생성) → `/extraction/validate`(OWL/SHACL) → 위반 표시 → `/extraction/save`. 분기: 안전(검증 실패)은 앞, 저장은 승인 게이트 뒤.
- **문장→규칙→SHACL 파생(단일소스)**: 지식 문장 → (LLM) 구조화 DesignRule(조건·증상·극성·카테고리) → (컴파일러 `gen_shacl`) SHACL·인과엣지·사람뷰. **문장이 진실원**, 규칙·SHACL은 파생(직접 편집 없음). 프로젝트 satisfy는 **프로젝트 선택 카테고리로 규칙 필터**(`project_scope_demo`). 엔지니어에겐 문장+파생 요약만.
- **satisfy**: 설계 인스턴스 + 요구거동 → (1)정성 subsumption(HermiT) → (2)SHACL 게이트 + 구간 비교기 → (3)무증상 규칙 → {satisfies, justification, violations, 대안}.
- **Q&A 하이브리드**: 질문 분류(A/B/C) → A:SPARQL / B:satisfy / C:RAG(검색→검증→답). 전부 환각비교 대조기로 LLM 단독과 병렬.

## 4. LLM Core / 프롬프트

- **AI Gateway**(계승): Strategy 패턴 Mock/Claude/Gemini. 키 없으면 Mock. 모델은 env(`GEMINI_MODEL` 등) fallback.
- **에이전트별 4요소**:
  - 추출기: 역할(개념/관계 추출), 출력=**Structured Output**(아래 스키마), 맥락=M0-ext 범주·7관계, 할루시네이션 방지=범주 밖 금지·근거 문장 인용.
  - Q&A: 역할(근거 기반 답), 출력=자유+출처, 맥락=RAG 검색 문장, 방지=검증 실패 시 "근거 없음".
- **Temperature**: 추출 낮음(0~0.2, 결정성), Q&A 중간.
- **추출 Structured Output 스키마**:
```json
{ "concepts":[{"label":"소음","type":"Symptom"}],
  "relations":[{"subject":"고무","predicate":"causes","object":"소음","evidence":"S1"}] }
```
type ∈ {PartType,Component,Material,VehicleType,EnvCondition,Symptom,…}, predicate ∈ {causes,mitigates,aggravates,conditionedOn,hasMaterial,has_part,…}.

## 5. 지식베이스 / RAG (하이브리드)

- **트리플스토어**: Oxigraph 임베디드(영속·SPARQL 1.1). rdflib API는 `oxrdflib` 스토어 플러그인으로. reasoner는 대상 서브그래프를 rdflib Graph로 뽑아 HermiT/pySHACL 실행.
- **임베딩 대상**: 각 `KnowledgeSentence`의 sentenceText(+개념·규칙 설명). 메타데이터에 **RDF IRI·aboutSymptom·derivesRule** 저장 → 검색 결과가 그대로 온톨로지로 연결.
- **벡터 인덱스**: Chroma 임베디드(영속). 임베딩=다국어 sentence-transformers(로컬, 한국어 지원) + MOCK 폴백(키/모델 없이 흐름 검증).
- **하이브리드 검색 평가**: 자유질의 시 top-k 검색 → 검색 문장의 규칙을 SPARQL/SHACL로 **검증**한 뒤에만 답에 사용("충분성" 판단). 검증 실패분은 답 근거에서 제외.
- **저장 동기화**: /save 시 트리플스토어 upsert와 벡터 upsert를 함께(IRI 일치). 삭제도 동기.
- **지식 카테고리·프로젝트 선택**: KnowledgeSentence를 카테고리로 그룹화, Project가 적용 카테고리 선택 → satisfy·검증은 선택 지식 규칙만(참조: `project_scope_demo` — 프로젝트 A 4위반 / B 3위반).

## 6. API 명세

**BFF (Node, 외부 노출)**
```
POST /api/v1/extraction/stream   (SSE) — 추출 스트리밍
POST /api/v1/extraction/validate — 지식서비스 위임
POST /api/v1/extraction/save     — 승인 저장(HITL 게이트)
POST /api/v1/satisfy             — 설계검증
POST /api/v1/qa                  — Q&A(A/B/C 분기) + 환각비교
GET  /api/v1/graph               — 지식맵(SPARQL 결과)
GET/POST /api/v1/upper-ontology/*  · /api/v1/spec/*  · /api/v1/rules/*  (관리자 게이트)
GET  /api/v1/health
```
**지식 서비스 (Python, 내부)**
```
POST /validate/shacl · /reason/consistency · /reason/classify
POST /satisfy         · POST /sparql (읽기)  · POST /kg/save · /kg/delete
POST /rag/search      · /rag/upsert
```
- **요청/응답**: Pydantic(입력 min/max·enum 범주). thread_id 자동. **에러 모델**: 공통 기본 예외 + 유형별(LLM/Store/Reasoner/RAG), 내부원인↔사용자메시지 분리.
- **스트리밍**: 추출은 SSE(단방향). 나머지 동기 REST(2s 이내 목표, satisfy는 캐시).

## 7. Frontend 명세

- **IA/화면**(Phase 4): 엔지니어(대시보드·지식입력·설계검증·지식맵·Q&A/환각비교·설계비교) / 관리자(상위 온톨로지·도메인 규칙·거버넌스). 상단 역할 전환.
- **상태관리**: Zustand(useAuthStore·useKnowledgeStore·useAIStore). thread_id·대화기록 세션 상태.
- **SSE 소비**: 추출 스트림 → 실시간 엔티티 하이라이트. **에러 UX**: 기술 메시지 대신 다음 행동 안내(타임아웃·연결실패).
- **답변 구조 순서**: 핵심 답 → 근거(검증) → 주의 → 출처(문장·규칙).
