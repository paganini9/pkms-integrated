## SC-1 — 암묵지 입력 → 구조화 → 지식맵  *(P1, P0)*

- **트리거**: 엔지니어가 설계 경험을 남기려 한다. "겨울철에 고무 블레이드는 경도가 올라가 소음이 난다."
- **사용자 흐름**: SmartInput에 자연어 입력 → SSE로 개념·관계 실시간 하이라이트(겨울철·고무·소음 / 겨울철→소음) → 추출 결과 미리보기 → **명세검증(OWL/SHACL)** 통과 → 저장 → 지식맵 반영(S1 지식문장 노드로). 저장 시 LLM/컴파일러가 규칙·SHACL을 파생하고, 엔지니어에겐 **문장 + 파생 요약**만 보인다(규칙·SHACL 직접 편집 없음; 편집은 문장 편집→재파생).
- **기대 결과**: `KnowledgeSentence` 노드 등록 + mentions/aboutSymptom(Noise)/derivesRule(NoiseRule) 자동 연결, 지식맵 표시.
- **예외/실패**: 추출이 `경도 —causes→ 겨울철`처럼 range 위반 생성 → ⛔ 경고("causes 치역은 Symptom") → 수정 유도. LLM 미가용 → Mock 폴백.
- **시스템 관점**: `/extraction/full`(생성) → `/extraction/validate`(reasoner 검증) → `/extraction/save` → Neo4j + RDF 투영.
- **연결 기능/화면**: SmartInput, 명세검증 패널, 지식맵.

> **입력의 두 종류 구분**: SC-1은 **도메인 지식**(M1, 재사용). SC-1P는 **프로젝트 요구사항**(M2, 프로젝트 종속). 화면·데이터에서 분리한다. 지식은 카테고리로 관리되고 프로젝트가 적용 지식을 선택하며, 엔지니어의 편집 대상은 **자연어 문장뿐**(규칙·SHACL은 파생·표시 — [지식-저작-상호작용-검토.md]).

## SC-1P — 프로젝트 요구사항 정의 (자연어 → RB)  *(P1, P0)*  ★ 신규

- **트리거**: 엔지니어가 새 프로젝트(예: 겨울용 SUV 와이퍼)의 설계 요구를 정의한다.
- **사용자 흐름**: 프로젝트 선택/생성 → 대상 컨텍스트(차종·환경) → **적용 지식(카테고리) 선택** → **자연어 요구 입력**("겨울철에도 소음이 없고 중형 SUV에서 떨림이 없어야 한다") → LLM이 RB 절로 파싱(`¬∃exhibits.소음 ⊓ ¬∃exhibits.떨림`) → 미리보기·검증 → 확인·저장(명명 요구셋).
- **기대 결과**: 프로젝트에 RequiredBehavior 저장(M2), satisfy에서 자동 사용.
- **예외/실패**: 요구가 **M1에 없는 증상**(예: "시야 미확보")을 참조 → "이 증상의 도메인 지식이 없습니다. 지식으로 추가?" → SC-1로 유도. 서로 모순된 요구는 경고.
- **연결 기능/화면**: 신규 S-02b 프로젝트 요구사항, AI Gateway(파싱), 명세검증.

## SC-2 — 설계 검증 satisfy  *(P1, P0)*  ★ 온톨로지 핵심

- **트리거**: 엔지니어가 프로젝트(예: 겨울용 SUV)에서 "이 설계가 프로젝트 요구를 만족하나?" 확인. 프로젝트 요구셋(RB)은 SC-1P에서 이미 정의됨.
- **사용자 흐름**: 프로젝트 선택 → **요구셋(RB) 자동 로드**(겨울 저소음 ∧ 떨림 없음) → 설계 인스턴스 입력(재질=고무, 길이=600mm, 스프링=8N, 암형상=simple, 차종=중형SUV) → **[satisfy 실행]** → `DB ⊑ RB?` 판정.
- **기대 결과**: **불성립** → 위반 규칙 자동 지목: S1(고무·겨울→소음), S3(≥600→떨림), S4(<10N 악화), S6(simple 악화) + justification. **허용 대안 제시**: 실리콘 / ≤599mm / ≥10N / complex.
- **예외/실패**: 요구거동 미선택 → 안내. 수치 누락 → SHACL 필수속성 경고. 반대로 실리콘·550mm·12N·complex·세단이면 → **satisfy ✔**(S2·S5 근거).
- **시스템 관점**: 설계 인스턴스 TTL 직렬화 → satisfy 엔진(EL subsumption + SHACL 수치 게이트) → {satisfies, justification, violations, 대안}.
- **연결 기능/화면**: 설계검증 화면(신규), reasoner/satisfy, SHACL 게이트.

## SC-3 — 환각비교 Q&A  *(P1, P0)*  ★ 시연 1급

- **트리거**: 엔지니어가 자연어로 질문. "중형 SUV에 고무 블레이드 600mm 써도 될까?"
- **사용자 흐름**: 질문 입력 → **[LLM 단독]** 답변 ‖ **[온톨로지 검증]** 답변 나란히 표시 → 불일치 하이라이트.
- **기대 결과**: LLM 단독="가능"(환각) vs 온톨로지="S3·S1 위반 — 떨림·소음, 대안 실리콘/≤599mm" + 출처(문장). **신뢰지표**(LLM→위반율, 일치율) 표시.
- **예외/실패**: 도메인 밖 질문 → 온톨로지 "명세 근거 없음" 명시(억지 답 금지). LLM 지연 → 스트리밍 상태 표시.
- **시스템 관점**: 온톨로지 경로 = Condition Graph 질의 + SHACL 검증 / LLM 경로 = 자유 생성 → 대조기.
- **연결 기능/화면**: Q&A(Layer A/B), 환각비교 모드.

## SC-4 — 지식맵 탐색·추적  *(P1, P0)*

- **트리거**: "떨림에 관련된 지식이 뭐가 있지?" 탐색.
- **사용자 흐름**: 지식맵 열기 → 증상 필터=TipChatter → 관련 문장(S3·S4·S5·S6)·규칙(ChatterRule·AggravationRule)·개념(길이·스프링·형상) 하이라이트 → 문장 노드 클릭 → 원문·mentions·출처.
- **기대 결과**: 층별(M0/M1/M2)·증상별·문장별 필터, 추론(inferred) 관계 점선, 출처 추적.
- **예외/실패**: 노드 과다 → 필터·레이아웃 조정. 고립 노드 시각 표시.
- **연결 기능/화면**: 통합 지식맵 뷰.

## SC-5 — 설계안 비교(VisualDiff)  *(P1, P1)*

- **트리거**: 두 설계안(고무 600mm vs 실리콘 550mm)을 비교.
- **흐름**: 두 설계 서브그래프 나란히 → 차이 강조 + 각 satisfy 결과 대비.
- **연결**: VisualDiff + satisfy.

## SC-6 — 상위 온톨로지 편집·일관성 검사  *(P2, P0)*

- **트리거**: 관리자가 M0/M1-mid에 범주·관계 추가 또는 satisfy 관계 조정.
- **사용자 흐름**: 상위 온톨로지 화면 → 클래스/관계 편집(다중 상위클래스·특성 배지 EL/OWL2·DL 수식 미리보기) → **[일관성 검사]** reasoner → 결과 + **M1 영향분석**(깨지는 subClassOf 미리 탐지).
- **기대 결과**: 편집·DL 미리보기·일관성(OK/모순)·영향분석.
- **예외/실패**: disjoint 위반 도입 → 차단·설명. 권한 없음 → 403.
- **연결 기능/화면**: 상위 온톨로지 편집기(관리자), reasoner.

## SC-7 — 도메인 규칙·SHACL 관리·영향분석  *(P2, P0)*

- **트리거**: 관리자가 6문장 규칙/제약 수정. 예: SUV 안전길이 599→595mm.
- **사용자 흐름**: 도메인 명세 화면 → DesignRule/SHACL 편집 → **dry-run**(임시 M2로 검증 미리보기) → 저장 → **영향분석**(새로 위반되는 M2 인스턴스).
- **기대 결과**: 규칙 편집·dry-run·영향분석.
- **예외/실패**: SHACL 문법 오류 → 실시간 검증. 대량 위반 발생 → 경고 후 확인.
- **연결 기능/화면**: 도메인 명세/SHACL 빌더, reasoner.

## SC-8 — 거버넌스(custom·권한)  *(P2, P0)*

- **트리거**: 관리자가 custom 클래스/관계 추가·삭제, 역할 관리.
- **사용자 흐름**: custom 개념·관계 생성(ID 충돌검사) / 삭제(builtin 잠금) / 관리자 역할 토글.
- **기대 결과**: custom CRUD, builtin 보호, 권한 게이트.
- **예외/실패**: builtin 삭제 → 400(BUILTIN_LOCKED). 일반 사용자 편집 → 403.
- **연결 기능/화면**: 상위 온톨로지 관리, 권한 미들웨어.

## 핵심 루프 — 사용자 관점 ↔ 시스템 관점

MVP의 중심 사슬은 **SC-1 → SC-2 → SC-3**이다.

| 사용자가 보는 것 | 내부에서 도는 것 |
|------------------|------------------|
| 지식 문장 입력·하이라이트 | `/extraction/full`(LLM) + 엔티티 스트리밍 |
| "검증 중" | `/extraction/validate` → reasoner(EL) + SHACL |
| 위반/통과 표시 | 위반=SHACL 게이트, 도출=EL 분류, 근거=justification |
| 설계 satisfy 판정 | 설계 TTL 직렬화 → satisfy(DB⊑RB) 엔진 |
| LLM vs 온톨로지 대조 | 두 경로 병렬 실행 → 대조기 → 신뢰지표 |
