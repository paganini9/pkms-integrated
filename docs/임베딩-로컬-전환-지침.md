# 임베딩 정합 지침 — Phase 1 코드 ↔ 결정(로컬·MiniLM 384·EMBEDDING_PROVIDER)

> 상황: Phase 1(02 데이터·03 RAG·04 그래프코어·06 퍼시스턴스)까지 진행된 **이후**에 "임베딩 = 로컬" 결정이 확정됐다.
> **실측 결과(코드 확인): 재작업 없음.** 개발팀은 임베딩을 처음부터 **로컬 sentence-transformers(`StEmbedder`) + MOCK 폴백**으로 구현했고, **Solar 임베딩 코드는 아예 없다.** 즉 "Solar→로컬 교체" 작업은 존재하지 않는다.
> 남은 일은 **문서 표기와 코드 표기를 통일하는 리네임** + **모델/차원 확정**뿐이다.

## 0. 결정 (2026-07-10 확정)

- **임베딩 = 로컬**(sentence-transformers). Solar 임베딩은 옵션(미구현).
- **기본 st 모델 = MiniLM 다국어 384**(`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`) — 코드 현재 기본값 **그대로 유지**(변경 없음). 대안 bge-m3(1024)·ko-sroberta(768).
- **설정명 통일 = `EMBEDDING_PROVIDER`**(문서 표기 채택) — 코드의 `EMBEDDING_MODE(mock|st)`를 `EMBEDDING_PROVIDER(mock|local|solar)`로 리네임. 값 `st`→`local`.
- **개발 기본값 = `mock`**(MOCK-first, 무의존 동작). 실임베딩은 `local`(=StEmbedder, `requirements-ml.txt` 필요).

## 1. 왜 "작은 변경"인가 (근거)

- **로컬 임베딩이 이미 구현됨** — `knowledge/rag/embedder.py`의 `StEmbedder`(sentence-transformers, lazy import) + `MockEmbedder`(해시 결정론). `get_embedder()`가 `settings.embedding_mode`로 분기, `st` 실패 시 mock 폴백(죽지 않음).
- **Solar 임베딩은 처음부터 없음** — 뜯어낼 코드가 없다. 결정과 코드가 사실상 일치.
- **모델 결정 = 현행 유지** — 코드 기본값이 이미 MiniLM 384. 모델 변경조차 없다.
- **변경 폭 = knowledge/rag·config + 설정/문서 텍스트** — BFF·frontend·G0 계약(`/rag/search`·`/rag/upsert` 시그니처)·satisfy·그래프코어 **전부 불변**. 크로스-서비스 조율 불필요.

## 3. 반드시 처리할 것 (gotcha)

1. **컬렉션 재인덱싱** — `mock`(256) ↔ `local/MiniLM`(384)는 차원이 달라, 이미 색인된 벡터와 섞이면 Chroma가 **차원 불일치 오류**를 낸다. provider를 바꾸면 `knowledge/data/chroma`를 **삭제**한 뒤 재기동(`get_retriever`가 `ensure_indexed` 재실행) 또는 컬렉션 drop→recreate. 시드 6문장이라 비용은 0에 가깝다. (선택 하드닝: 컬렉션 메타에 모델·차원을 저장해 불일치 시 자동 재생성.)
2. **test#6 전제 유지** — `test_st_mode_falls_back_to_mock`은 "sentence-transformers **미설치** 시 mock 폴백"을 검증한다. 기본 CI는 `requirements.txt`만 설치(=ML 미포함)하므로 그대로 통과한다. **`requirements-ml.txt`를 기본 CI에 넣지 말 것**(넣으면 이 테스트가 StEmbedder를 받아 실패). 실제 ST 검증은 ML 설치 잡에서 별도 opt-in 테스트로.
3. **모델 다운로드** — `local` 첫 실행 시 MiniLM(~120MB) 다운로드 후 오프라인. Docker는 이미지에 굽거나 볼륨 캐시. (bge-m3로 상향 시 ~2.2GB.)
