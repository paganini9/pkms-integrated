## 2. 전역 요소

- **역할 전환**: 상단 토글. 엔지니어↔관리자. 관리자 화면은 권한 게이트(비관리자는 숨김/403).
- **모드 배지**: Mock/실제 AI, LPG/RDF 상태. 시연 시 명확히.
- **면책 공통**: "AI 추출·응답은 명세로 검증되며, 미검증 항목은 근거 없음으로 표시됩니다."

## 3. 화면별 요구사항

### S-01 대시보드 (엔지니어 홈)
- **목적**: 지식 규모·검증 상태·최근 활동을 한눈에.
- **필수요소**: M0/M1/M2 상태 카드(클래스·규칙·인스턴스 수, 유효/위반), 최근 입력·검증, 빠른 입력 버튼.
- **상태표현**: 로딩 스켈레톤, 빈 상태("첫 지식을 입력하세요").
- **5초 테스트**: "지식이 얼마나 쌓였고 얼마나 건강한가."

### S-02 지식입력 (SmartInput) — HTML 목업
- **목적**: 자연어 암묵지를 구조화해 검증·저장.
- **필수요소**: 자연어 입력창, 실시간 추출(개념 chip·관계 목록), **명세검증 패널**(위반=amber 경고), **파생 규칙·SHACL 요약(읽기 전용)**, [저장]. 편집은 문장 편집 → 규칙·SHACL 재파생(직접 편집 없음).
- **사용자 행동**: 입력 → 추출 확인 → 위반 수정 → 저장.
- **상태표현**: SSE 스트리밍("추출 중…"), 검증중, 위반(⛔ range 위반), 성공(✓).
- **면책**: "추출 결과는 명세 검증 후 저장됩니다."

### S-02b 프로젝트 요구사항 (자연어 → RB) ★신규
- **목적**: 특정 프로젝트의 요구사항(RequiredBehavior)을 자연어로 정의(M2). **도메인 지식 입력(S-02)과 구분** — "지식"이 아니라 "이 프로젝트의 요구".
- **필수요소**: 프로젝트 선택/생성, 대상 컨텍스트(차종·환경), **적용 지식(카테고리) 선택**, 자연어 요구 입력창, LLM 파싱 결과(RB 절·형식 미리보기 `¬∃exhibits.증상`), 검증(미지 증상→지식 유도), [요구셋 저장].
- **상태표현**: 파싱중, 미지 증상 경고(지식 추가 유도), 모순 경고, 저장 성공.
- **면책**: "요구는 이 프로젝트에만 적용됩니다(도메인 지식과 별개)."

### S-03 설계검증 (satisfy) — HTML 목업 ★신규
- **목적**: 프로젝트 설계안이 **프로젝트 요구(RB)**를 만족하는지 기계 증명.
- **필수요소**: 프로젝트 선택 → **요구셋 자동 로드**(SC-1P 정의), 설계 인스턴스 폼(재질·길이mm·스프링N·암형상·차종), [satisfy 실행], **결과 카드**(✔/✘ + 위반 문장·규칙 + justification + 허용 대안).
- **사용자 행동**: 설계 입력 → 요구 선택 → 실행 → 근거 확인 → 대안 반영.
- **상태표현**: 추론중, 만족(초록), 불만족(빨강+위반칩), 값 누락(SHACL 경고).
- **면책**: "판정은 OWL 추론 + SHACL 게이트의 결정론적 결과입니다."

### S-04 지식맵
- **목적**: 다층 지식을 탐색·추적.
- **필수요소**: 그래프 캔버스, 층/증상/문장 필터, 범례, 상세 패널(출처·mentions), inferred 점선.
- **상태표현**: 로딩, 노드 과다 시 필터 유도, 고립 노드 표시.

### S-05 Q&A·환각비교 — HTML 목업 ★시연
- **목적**: LLM 단독 vs 온톨로지 검증을 대조해 환각을 드러냄.
- **필수요소**: 질문 입력, 3-토글(LLM/온톨로지/비교), **좌우 대조 패널**, 불일치 하이라이트, 신뢰지표(위반율·일치율), 출처.
- **상태표현**: 스트리밍, 근거 없음("명세 밖"), 불일치 경고.
- **면책**: "왼쪽은 검증 전 LLM 원답변입니다."

### S-06 설계안 비교 (VisualDiff)
- **목적**: 두 설계 서브그래프·satisfy 결과 비교.
- **필수요소**: 좌우 그래프, 차이 강조, satisfy 대비.

### S-07 상위 온톨로지 (관리자)
- **목적**: M0/M1-mid 클래스·관계·satisfy 유지·검증.
- **필수요소**: 클래스/관계 편집(다중 상위·특성 배지·DL 수식), 지식맵, [일관성 검사], **M1 영향분석**.
- **상태표현**: 모순 감지(빨강+설명), 저장 성공.

### S-08 도메인 규칙·SHACL (관리자)
- **목적**: 문장→규칙→SHACL 파생 검토·카테고리 관리(직접 SHACL 작성 아님).
- **필수요소**: 규칙·SHACL **생성 뷰**(문장에서 파생), 카테고리 관리, **dry-run**, 영향분석. raw-SHACL 직접 편집은 예외적 escape hatch(고급 전용).

### S-09 거버넌스 (관리자)
- **목적**: custom 개념·관계·권한·버전.
- **필수요소**: custom CRUD(builtin 잠금), 권한/역할, 변경이력.

## 4. ASCII 와이어프레임 (비목업 화면)

**S-01 대시보드**
```
┌ PKMS · 엔지니어 ────────────────[역할 전환][Mock]─┐
│ ┌M0 상위┐ ┌M1 규칙┐ ┌M2 인스턴스┐ ┌검증┐        │
│ │ 12클래스│ │ 3규칙 │ │ 9개(유효5)│ │위반3│        │
│ └───────┘ └──────┘ └──────────┘ └────┘        │
│ 최근 활동                         [+ 지식 입력] │
│  · S1 소음 문장 저장 (방금)                      │
│  · Blade-001 satisfy ✘ (5분 전)                  │
└──────────────────────────────────────────────────┘
```

**S-04 지식맵**
```
┌ 지식맵 ──────────── 필터: [층▾][증상: 떨림▾][문장▾] ┐
│  ┌범례┐   (Winter)──causes──►(Noise)                │
│  │층색 │   (SUV)──maxSafe 599──(길이)                │
│  └────┘   (S3)┈derives┈►(ChatterRule)──►(TipChatter)│
│  선택: 문장 S3                                       │
│   원문: "중형 SUV 길이 600mm↑ → 끝단 떨림"           │
│   출처: 6문장 §3 · mentions: SUV·TipChatter          │
└──────────────────────────────────────────────────────┘
```

**S-07 상위 온톨로지**
```
┌ 상위 온톨로지 (관리자) ─────────────────────────┐
│ [클래스][관계][지식맵]         [+ 신규][일관성검사]│
│ Behavior                                          │
│  ├ RequiredBehavior   상위: Behavior  특성: —      │
│  └ DesignedBehavior   ⊑ Behavior      satisfy▸RB   │
│ DL: DesignedBehavior ⊑ Behavior                   │
│ 영향분석: M1 subClassOf 3건 정상                   │
└───────────────────────────────────────────────────┘
```

**S-08 도메인 규칙·SHACL**, **S-09 거버넌스**, **S-06 비교**는 각 요구사항(§3) 기준으로 유사 레이아웃 — 필요 시 다음 라운드에서 상세화.

## 5. UI 원칙 & 검증
- 근접·정렬·대비·반복. 상태(로딩/스트리밍/에러/빈/위반) 항상 명시. 출처·근거 최우선.
- **5초 테스트**: 각 화면 상단에 "무엇을 하는 곳인지" 한 줄.
- **다음(Phase 5)**: 추적성(시나리오↔기능↔화면) 최종 점검 후 허브에 저장 → 개발요구사항 Agent 연결.
