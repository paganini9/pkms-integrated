# 작업 분해 · 의존성 맵 (병렬화 계획)

> 오케스트레이터가 `task_board.md` 초기화 시 사용하는 기준. DAG·게이트·병렬 묶음 정의.

## 1. 의존성 DAG

```
        ┌────────────────────────── Phase 0 (직렬) ──────────────────────────┐
        │ 01 아키텍처·표준                                                    │
        │   → 레포 골격 + contracts/{api_standard, interface_contracts,       │
        │     error_model, state_schema, mocks} freeze                         │
        └───────────────┬─────────────────────────────────────────────────────┘
                        │ [게이트 G0: 계약 freeze]
        ┌───────────────┴───────────────── Phase 1 (병렬) ────────────────────┐
        │ 02 데이터        03 RAG          06 퍼시스턴스(DB·FS)               │
        │ (data/)          (rag/)          (store/ + 스키마)                   │
        │        04 그래프·코어 (graph/+llm/) ── data/rag는 mock으로 선행      │
        └───────────────┬─────────────────────────────────────────────────────┘
                        │ [게이트 G1: 레이어 인터페이스 적합성]
        ┌───────────────┴───────────────── Phase 2 (통합) ────────────────────┐
        │ 05 백엔드·API (04+06 결합, /chat SSE)                                │
        │        → 07 프론트엔드 (API 소비; mock API로 선행 가능)              │
        └───────────────┬─────────────────────────────────────────────────────┘
                        │ [게이트 G2: E2E 시나리오 동작]
        ┌───────────────┴───────────────── Phase 3 (검증·패키징) ─────────────┐
        │ 08 QA(상시·게이트)        09 DevOps(Docker·패리티)                   │
        └─────────────────────────────────────────────────────────────────────┘
```

## 2. 게이트 정의
- **G0 계약 freeze**: API 표준·인터페이스 계약·에러 모델·State 스키마·mock fixtures 확정 → Phase 1 착수 허용.
- **G1 인터페이스 적합성**: 02·03·04·06 산출물이 계약 스키마 검증 통과(실/모의 무관).
- **G2 E2E**: SC-A 한 줄 결론→섹터·코인→출처가 프론트에서 끝까지 스트리밍.
- **릴리스**: 오케스트레이터 §5 통합 게이트 전 항목 통과.

## 5. 임계 경로(Critical Path)
`01 계약(G0) → 04 그래프 코어 → 05 API(G2) → 08 QA 게이트 → 09 패키징`.
데이터·RAG·퍼시스턴스·프론트는 임계 경로와 **겹치지 않게 병렬**로 흡수해 총 기간 단축.
