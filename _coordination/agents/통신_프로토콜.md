# Agent 통신 프로토콜

> Agent들은 **공유 파일 + 오케스트레이터**로 소통한다(직접 호출 아님). 모든 메시지는 아래 양식을 따른다.
> 위치: `_coordination/`.

## 1. 통신 채널

| 채널 | 파일 | 소유 | 용도 |
|---|---|---|---|
| 작업 보드 | `task_board.md` | 오케스트레이터 | task 할당·상태·의존성 |
| 계약 | `contracts/*` | 01(작성)·오케(승인) | API·인터페이스·에러·State·mock |
| 상태 보고 | `status/<agent>.md` | 각 Agent | 진행·산출·블로커·요청 |
| 통합 로그 | `integration_log.md` | 오케스트레이터 | 체크포인트 결과 |

## 2. 메시지 양식 (status/ 및 보드에 append)

```
### [MSG] 2026-07-01T10:00 / FROM:04-graph / TO:00-orch
TYPE: request | deliver | blocker | contract-change | review
REF: contracts/interface_contracts.md#data_collector, task:T-12
BODY:
- (요청/완료/차단 내용 1~3줄)
NEEDS: (상대가 해줘야 할 것, 없으면 생략)
```

- **TYPE 의미**: request(작업·정보 요청) / deliver(완료 인계) / blocker(막힘) / contract-change(계약 변경 제안) / review(검토 요청).
- 모든 메시지는 **REF로 계약·task를 명시**(추적성).

## 3. 인터페이스-우선 핸드셰이크 (병렬화의 핵심)

두 Agent가 맞닿는 지점:
1. 소비자 Agent가 필요한 **입출력 타입**을 `contracts/interface_contracts.md`에 초안 제시(`contract-change`).
2. 제공자 Agent + 오케스트레이터가 합의 → 계약 **freeze + 버전**.
3. 양측은 계약을 만족하는 **mock**으로 즉시 병렬 착수(실구현 대기 안 함).
4. 실구현 완료 시 mock 교체, 계약 적합성 테스트 통과로 인계(`deliver`).

## 4. 계약 변경 절차 (Change Control)
1. `contract-change` 메시지로 변경안 + 사유 제출.
2. 오케스트레이터가 **영향 Agent 식별** → 승인/반려.
3. 승인 시: 계약 **버전업(vN→vN+1)** + 변경 로그 + 의존 Agent에 통지 + `task_board`에 마이그레이션 task.
4. 무단 변경 금지. 계약 위반 산출물은 통합 게이트에서 반려.

## 5. 동기화 규칙
- 각 Agent는 작업 시작/완료 시 `status/<agent>.md`를 갱신(최소: 현재 task, %, 블로커).
- 공유 파일(계약·`main.py` router include·`docker-compose.yml`)은 **오케스트레이터만** 병합.
- 충돌 예방: 자기 담당 경로 밖 수정 금지. 교차 수정 필요 시 `request`로 위임.
