**음성 테스트(검증기가 no-op 이 아님을 증명):**
- 화이트리스트 밖 `query` → **422 VALIDATION_ERROR** (`test_lookup_rejects_query_outside_whitelist`).
- SPARQL 주입 시도 `params={"vehicle":"> ?x } DELETE {..."}` → **200 빈 결과**. `initBindings` 로 무해한 IRI 로 바인딩돼 질의 구조가 안 바뀐다(`test_lookup_injection_attempt_is_harmless`, `..._does_not_mutate_store`).
- builtin 개념 삭제 → **400 BUILTIN_LOCKED**. 미승인 개념 생성 → **409 GUARDRAIL_BLOCKED**.
- `inferred` 는 실제 추론임을 단언: `has_subbehavior`(owl:TransitiveProperty)의 이행 폐포 `WipingBehavior⇝ContactBehavior` 가 `inferred:true` 로 나온다(`test_graph_full_has_real_inferred_edge`).

## 발견한 결함·계약 모순
- **없음(신규 계약 모순).** §1.2 가 신설분의 스키마를 명시해 06 소관에서 새 모순은 없었다.
- **주입 방어 핵심**: `params` 는 반드시 rdflib `initBindings` 로만 바인딩했다. SPARQL 문자열 f-string 보간은 lookup 경로 어디에도 없다(질의는 전부 상수 문자열). 프로토타입으로 `599/S3` 및 주입 무해를 먼저 실증한 뒤 구현했다.
- **결정론 확인**: SPARQL/SHACL 결과 순서에 의존하지 않도록 rows·nodes·edges·sources 를 전부 정렬한다(G1 결함 재발 방지). `test_graph_is_deterministic` 로 단언.
- **멱등 유지**: `createdAt` 추가에도 `load_seed` 재적재·트리플 롤백 카운트 불변(기존 `test_load_seed_idempotent`·`test_kg_save_atomic_rollback` 통과). 시드 문장에는 createdAt 를 넣지 않는다.

## 알려진 한계 (정직하게)
- **`inferred` 엣지는 실제로 만들었다.** 시드에 존재하는 유일한 추론원인 `has_subbehavior` 이행성으로 `WipingBehavior→ContactBehavior` 1건이 나온다. 그 밖의 추론(subClassOf 사슬 등)은 지식맵 노이즈를 피하려 엣지로 만들지 않았다 → 추론 엣지가 없는 뷰에서는 `inferred_edges:0` 으로 정직하게 0 이다.
- **M2 카운트/그래프는 스토어 상태를 그대로 반영한다.** `config.seed_ttl` 은 `m2_instances.ttl` 을 **의도적으로 제외**(프로젝트는 런타임 생성)하므로, 아무 프로젝트도 만들지 않은 초기 스토어에서 `/dashboard` 의 `m2.projects/designs/violations` 는 정직하게 0 이고 `recent` 는 `[]` 다. 프로젝트를 생성하면 M2 노드·recent 가 채워진다(`test_graph_project_appears_as_m2`, `test_dashboard_recent_reflects_saved_project`).
- **`dashboard.m2.violations`** 는 저장된 설계 인스턴스(eng:*)를 시드 SHACL 게이트로 pySHACL 검사해 센다. 기본 스토어엔 설계가 없어 0 이다(위와 동일 이유). 판정을 다시 돌리는 게 아니라 저장 인스턴스 대상 발화 카운트다.
- `recent` 의 `at` 은 **런타임 저장 시각**(생성 순서 근사)이다. 시드 데이터는 적재 시각을 모르므로 recent 에 넣지 않는다(가짜 타임스탬프 금지).
