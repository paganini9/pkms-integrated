## G2 재검증 수정 (CD-13, v1.4) — 실키(claude-opus-4-8)로 발견한 최심각 결함

`mode:"verified"` 인데 도메인 밖 질문이 **거짓 출처를 단 "검증 답변"** 을 냈다("타이어 공기압?" → `insufficient:false, sources:[S1]`).
원인 둘: (1) 도메인 접지(CD-12)를 `runLayerC` **안에만** 뒀는데 계층은 LLM 분류기가 고른다 → A/B 로 가면 접지 미실행.
(2) 각 계층이 **없는 입력을 지어냈다**: `mapNamedQuery` 무조건 폴백, `parseDesign` 기본 설계, C "알려진 개념 ≥1".

### 수정 (`routes/qa.ts` · `services/ai/claudeProvider.ts`)
1. **접지를 라우팅보다 앞으로.** `/qa` 진입 직후 `gateway.extract` → `POST /validate/shacl` 로 접지. **인식 개념 0 → 계층 무관 `insufficient:true, sources:[]`.**
2. **전 계층 fail-closed(입력 날조 금지):**

   - **C** — 미지 개념(`unknown_concept`) 1건이라도 → insufficient(가장 보수적).
3. **`insufficient:true` → `sources` 강제 `[]`.**
4. **추출기 도메인-엄격화**: ClaudeProvider extract 프롬프트에 "와이퍼 도메인 개념이 없으면 concepts/relations 를 빈 배열로" 명시.

### ⚠️ 막지 못한 우회 (숨기지 않고 보고)
**C계층의 도메인 접지는 완전 결정론이 아니다.** `/validate/shacl` 은 **관계**의 대상이 개념 목록에 없을 때만
`unknown_concept` 를 낸다 — **단독 개념의 온톨로지 소속은 판정하지 못한다**(실측 확인: `[자전거 Component]` → `conforms:true`).
지식서비스에 라벨→IRI 해석/개념 존재 조회 엔드포인트가 없고, `/sparql` 은 불변원칙 1 로 금지다.
따라서 C계층 접지는 **추출기가 도메인 밖 개념을 버려주는 것(LLM 의존)** + relation 기반 `unknown_concept`(결정론, 제한적)에 의존한다.
- **A·B 는 완전 결정론**(mapNamedQuery/parseDesign 정규식) — 추출기와 무관하게 fail-closed.
- **C 의 잔여 위험**: 추출기가 도메인 밖 문맥에서 **진짜 도메인 개념 하나(예: 실리콘)** 를 뽑아내고 C 로 분류되면,
  standalone 이라 `unknown_concept` 가 안 걸려 근거가 붙을 수 있다. 실키 테스트에선 도메인-엄격 프롬프트가 `[]` 를 반환해 막혔으나
  **이는 하드 보장이 아니다.** 완전 결정론화하려면 지식서비스에 **개념 존재/라벨 해석 조회**(예: `POST /concepts/resolve`) 신설이 필요하다 → **계약 변경 후보로 제출**.

## G2 재검증 수정 (CD-14, v1.5) — 근거 없는 answer() = 환각. 두 호출을 타입으로 분리

### 무슨 일이었나 (CD-13 이 옆에서 재발시킴)
`"중형 SUV에 고무 600mm 써도 될까?"`(스프링·암형상 미지정) → `parseDesign` 이 (CD-13 대로) 날조하지 않아
satisfy 가 CD-8 판정 보류(`satisfies:null`) → `violations` 빔 → `sources` 빔 → `runLayerB` 가 `gw.answer(question, [])` 호출.
그런데 `answer(q,[])` 는 환각비교의 `llm_answer` 를 만드는 바로 그 호출이라, **미검증 LLM 답변에 `determinism:"satisfy"` 라벨이 붙어 나갔다.**

### 수정 (`services/ai/*` · `routes/qa.ts`)
1. **호출을 이름으로 분리**(AIProvider 3 provider 전부 + Gateway):
   - `answer(question, sources)` — **`sources` 가 비면 `EmptyContextError` throw.** 검증 답변 전용.
   - `llmOnlyAnswer(question)` — 무근거 단독 답변. **환각비교의 `llm_answer` 에만** 쓴다.
   - Gateway.answer 는 빈 근거를 reliability·mock 폴백 이전에 즉시 reject(막다른 길에서 LLM 흘러내림을 타입으로 차단).
2. **`verified_answer.text` 는 `sources` 가 비면 LLM 이 생성하지 않는다.** 결정론 문자열만.

   뿐이고 적용 카테고리는 "프로젝트 지식범위" 라 했지만(CD-4), 지식서비스 `/satisfy` 내부 계약(§1.1)은
