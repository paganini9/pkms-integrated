## 발견한 결함 · 계약 모순
1. **`ValidateResponse`·`SaveResponse`·`RequirementsResponse`·`HealthResponse` 의 TS 타입이 `contracts.ts` 에 없었다.** 계약 §4.2/4.3/4.7/4.10 에는 응답 형태가 있으나 프론트 타입 소스에 누락 → 계약에 맞춰 타입 추가(계약 변경 아님).
2. **`extraction/save` fixture 의 요청에 `draft_id` 가 있으나 `api_standard.md §4.3` 요청 예시에는 `draft_id` 필드가 명시되지 않음.** stream `done` 이 주는 `draft_id` 를 save 로 넘겨야 자연스러운데 계약 본문 요청 스키마에 문서화가 빠져 있다. 프론트는 fixture 기준으로 `draft_id` 를 전송. → 05 백엔드가 save 요청 스키마에 `draft_id?` 를 반영할지 확인 필요.
3. **`derived.rule` 에 `about_symptom`·`basis` 필드가 fixture 엔 있으나 `api_standard.md §4.3` 응답 예시엔 없음**(예시가 축약형). 화면은 있으면 표시, 없어도 동작하도록 optional 처리.
4. **satisfy 판정 보류 필드 위치 불일치**: `api_standard.md §4.4` 는 경고를 `steps[1].warnings[]` 라 하고 CD-8 도 동일하나, §4.4 본문 마지막 줄은 "SHACL 경고를 `steps[1].checks` 에 실어 반환"이라고 다르게 적음. fixture(`satisfy_pending_missing.json`)는 `warnings[]` 를 씀 → 프론트는 fixture·CD-8 기준 `warnings[]` 를 렌더. **계약 §4.4 본문 두 문장이 상충**하니 정정 권고.

## 알려진 한계 (실 API 연결 시 주의)
- **Mock 라우팅은 입력 텍스트/폼값 휴리스틱**으로 fixture 를 고른다(예: material=Silicone→good, spring_n 결측→pending, "타이어"→insufficient). 실 BFF 연결 시 이 분기는 서버 응답으로 대체되므로 화면 로직엔 영향 없으나, mock 데모 시나리오는 정해진 입력에서만 의도대로 동작.
- **지식맵 필터는 mock 에서 클라이언트측 재필터**(mock `/graph` 는 단일 fixture 반환). 실 API 는 `?layer=&symptom=&sentence=` 를 서버가 처리 — "서버 조회" 버튼이 그 경로. 클라이언트 필터는 보조.
- **노드 클릭 출처추적**은 `/graph` 엣지의 `evidence`·연결 rule 노드에서 재구성. 실 API 가 노드 단위 출처를 별도로 주면 더 정확해질 수 있음(현재 계약엔 노드별 sources 필드 없음).
- **SSE 파싱**은 표준 `event:`/`data:` 라인 기준. BFF 가 멀티라인 data 나 `id:`/`retry:` 를 쓰면 파서 보강 필요(현 계약 §5 는 "단일 JSON 1줄"이라 문제 없음).
- 실 API 모드는 `vite.config.ts` 프록시(`/api`→BFF)와 `VITE_USE_MOCK=false` 로 전환. `X-Role` 헤더는 localStorage 역할값으로 전송(Mock-Role, CD-5).
